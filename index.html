Breadth before depth.

BREADTH-FIRST SEARCH

What is Breadth-First Search?

BFS is an uninformed search algorithm that explores states in order of their distance from the starting state. It visits all states one move away before states two moves away, and so on.

Why a FIFO queue?

First in, first out means the oldest waiting state is processed next. Newly discovered neighbors join the back. A discovered set prevents cycles and repeated work; parent pointers remember how each state was first reached.

Why is the solution shortest?

Every tile slide costs one move. Because BFS processes states in nondecreasing depth order, the first goal removed from the queue has minimum depth. Following its parent pointers back to the start recovers a shortest path.

The algorithm

PSEUDOCODE
validate(initial, goal)
if parity differs: return unsolvable
queue ← [initial]
discovered ← {initial}
parent[initial] ← null

while queue is not empty:
    current ← queue.dequeue()
    if current equals goal:
        return reconstruct(parent)
    for each legal neighbor:
        if neighbor not discovered:
            mark neighbor discovered
            parent[neighbor] ← current
            depth[neighbor] ← depth[current] + 1
            queue.enqueue(neighbor)

return frontier_exhausted

Properties & advantages

Complete
Graph BFS with duplicate detection finds any reachable goal in this finite puzzle graph.
Optimal
It returns a minimum-move path because every edge has the same positive cost.
Path cost
One unit per legal slide. A solution at depth d costs d moves.
Search depth
The number of edges from the start. The initial state is depth 0.
Easy to explain
A queue, discovered set, and parent map make the search straightforward to implement and visualize.

Complexity & limitations

Graph search: time O(V + E), space O(V). V is the number of reachable states and E the legal connections between them. An 8-puzzle parity component contains 181,440 states.

Tree-search estimate: time and space are commonly written O(bd), where b is the branching factor and d the shallowest goal depth. With goal checks on removal, a literal tree search may generate a level beyond d; some texts write O(bd+1) for generation time. These bounds summarize growth, not measured runtime.

BFS stores discovered states, parent information, and a potentially large frontier. Difficult puzzles take more time and memory. This application yields between batches and supports safe cancellation.

What do these numbers count?

Generated: unique discovered states, including the initial state. Expanded: dequeued and processed states, including the goal. Maximum depth: deepest discovered state, which can exceed the solution depth. Solution depth / moves: goal depth / number of path transitions.

Time: wall-clock milliseconds from performance.now(), including yielding and optional demonstration delays. Memory estimate: 96 bytes per discovered record plus 8 bytes per retained queue slot. It excludes browser, DOM, and trace overhead and is not a browser heap measurement.

Assigned algorithm: Breadth-First Search (BFS)

The problem

The 8-Puzzle contains eight numbered tiles and one empty cell on a 3 × 3 board. Only tiles next to the blank may slide. The task is to transform an initial arrangement into a chosen goal using the fewest legal moves.

Our approach

Represent arrangements as states in a graph. Apply parity validation, explore that graph with a FIFO queue, record parent pointers, and reconstruct the shortest solution once BFS dequeues the goal.

Objectives

  • Make state-space search visible and understandable.
  • Find a shortest path with genuine JavaScript BFS.
  • Connect real search data to interactive visualization.
  • Explain the cost of exhaustive search with honest measurements.

Built to be explored

  • Custom initial and goal states with parity validation.
  • Solvable random puzzles and legal manual moves.
  • Smooth tile animation with full playback controls.
  • Live frontier, explored states, successors, and bounded event logs.
  • Actual statistics and theoretical algorithm comparisons.

Technologies

HTML5, CSS3, CSS Grid, CSS transitions, and JavaScript ES modules. Static hosting with GitHub Pages; no application server or external AI service.

Learning outcomes

Understand graph representations, FIFO exploration, duplicate detection, parity, optimality for equal-cost moves, path reconstruction, and the time–space tradeoff of BFS.
